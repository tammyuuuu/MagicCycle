# 星循最小改造方案（待用户确认，尚未实施）

约束：复用 Flask、静态导出、五卡片、资金池纯函数、日记与状态展示。新策略账户初始空仓，2000元来自总金融资产10%的池子；历史持仓只参与总金融资产口径，不参与新池交易与盈亏。A股估值观察继续保留，不据此自动配置。

## 1. 首先修正研究验收基础

在现有引擎上增量补齐数据可得时刻、基金交易日历、确认日、真实到账规则、份额/费用舍入和现金分红；不用重写全部回测框架。按组合选取必要列，缺失过阈值立即失败，输出实际首尾日期、月数、源哈希与引擎版本。动态权重严格滞后；V2.1按持有期结束时间隔离训练和测试。

固定同一期间、同一成本，对比候选与同权重简单持有、货基、限购时可执行基准；增加新起点与压力段。注册表保持候选，未通过不生成正式操作。用户风险上限和渠道条件未确定前不擅自挑选 A/B/C/L1/L2。

验收：增加无关资产不得改变组合结果；截断未来数据不得改变历史信号；每笔成交可追到当时可见净值；不能提前使用应收款；输出真实覆盖日而非请求区间。

## 2. 账户与账本优先

扩展 `portfolio_store.js`，增加 `account_id`，至少 `legacy`（只读历史）和 `strategy`（新池）；可另有候选模拟账户。日记与现金流都绑定账户，未经用户映射不自动导入历史记录。总资产快照已经包含账户资产，不能再把2000加到总资产上。

新池以一笔2000元入金开始，不是既有持仓，也不是新增金融资产。以后上限变动只算可新增额度；超额暂停新增，不自动赎回。现金、申购冻结款、已确认持仓、赎回应收分开，避免漏记或重复计入净资产。

以不可变资金/交易事件为事实来源；更正使用冲销/替代事件，持仓和余额由基线与事件纯重放生成，不再从当前余额重扣。每笔订单有唯一id、批次、账户、策略版本、信号快照与确认凭证。保留日记的文本复盘能力，不能再以日记文本直接制造资金和份额。

验收：2000入金→买1000→重复刷新/重建仍现金1000；删除或更正成交可追溯；零持仓禁止卖出；未确认份额不入可卖持仓；失败退款回到现金；重复确认幂等；新旧账户互不污染。

## 3. 真实交易状态

建议→待执行→已提交→已确认/部分确认/失败/已取消。建议不影响余额；提交买入冻结支付金额，确认时按实际净值、份额、费用入账；失败释放冻结款。卖出提交冻结可卖份额，确认后形成应收款，实际到账事件才转可用现金。到账按订单逐笔确认，替代一次清空全部 receivable。

继续手动下单，不接自动交易。填写建议时只带代码、方向、建议金额和原因；不要把旧净值预填成真实成交价。确认表单要求真实份额、成交净值、费用，支持金额包含费用的明确口径。

## 4. 策略配置与限购

复用 strategy_registry.json 的研究记录，另规范可执行版本结构：唯一id（例如 `v23_fixed_40_30_30_candidate`）、状态、资产、固定/动态规则、月度检查日、2%带、最低金额、现金去向、数据时点和审计结果。旧版本归档但不删除；订单冻结当时版本，不随新版本重算。

`portfolio_data.py` 改为读取获批配置，继续生成只读行情快照。现有 inverse_vol 可供研究复用，固定候选无需新增动态求解器。权重月度冻结，持仓变化/已提交订单纳入计划，日常刷新不能反复生成同一买单。

申购和赎回状态分开；渠道、限额、当日已提交金额、更新时间和来源独立保存。状态未知/过期则显示阻断原因，不显示“交易带内无需操作”。纳指不可买时给出现金等待及经批准的限购配置比较，**不自动切L1/L2**。恢复后先核对份额、持有期、赎回费用、现金、额度和到账日，再生成有限期切换计划；不得套用旧K4切换成本。

## 5. 买卖金额

复用 `capital_pool.js` 和 Python 参考实现，修边界而非重写：剔除历史账户；可用现金扣冻结金额；在途不得使用；资产缺净值时暂停组合金额计算；限额截断后重新检查10元下限；按当日已提交量扣额度；份额FIFO和短期费用准确显示。

研究和网站统一买卖2%带以及月度执行节奏。金额保留到分，余分有确定分配规则，支付总额不超过可用余额。2000元配置表只作候选展示，确认真实可买条件后才形成待执行订单。

验收：真正同时运行Python与JS测试同一组输入，覆盖低限额、暂停买但可卖、过期净值、冻结款、零现金、在途、短期批次、重复提交等。

## 6. 月度真实盈亏与基准

复用月度卡片，改取账户日度净资产：现金＋冻结款＋确认持仓市值＋赎回应收（每笔只能在一个状态计值）。

月度盈亏=月末净资产−上月末净资产−当月外部净流入；手续费已经包含在净资产损益，单独展示明细时不能再扣一次。正确处理月中买卖、分红和到账，不把新增资金延后到下个月才算收益。数据缺失显示暂不可计算，不把缺失视作0。

收益率提供按资金流调整的时间加权收益；个人投入体验可另外用XIRR，不能直接用有大额流入月份的盈亏/月初资产。最大回撤基于资金流调整后的日度单位净值。

对照同时显示：同账户资金流、同初始配置的简单持有；同资金流货基；按真实限制执行的策略模拟。分开显示实际操作偏差与策略本身差异，并说明收益提升还是风险降低。

验收：月初100份月中清仓不再赚取清仓后收益；月中建仓的收益计入当月；入金不算盈利；到账不算新入金；新旧账户基准各自独立。

## 7. 备份恢复与手机

扩展已有JSON导入导出，完整包含账户、基线、事件、快照、策略版本、信号、订单、费用、来源与schema_version；不只备份日记。导入先校验和预览，按唯一id去重，冲突不静默覆盖；导入前保留旧数据备份。静态网页先做文件备份即可，不必立即开发登录和云同步。

手机复用五卡片与现有样式：首屏给出“何时检查/是否需要操作”；动作卡清楚显示基金、金额、原因、状态和有效期；确认成交和确认到账分步；窄屏表格改卡片；提供明显的备份入口和数据日期。

验收：360/390px宽度无关键字段遮挡；金额与按钮可单手操作；换浏览器导入备份后现金/份额/盈亏/待处理订单一致。实际手机浏览器验证留到开发阶段。

## 8. 建议实施顺序与交付边界

1. 修研究口径与执行约束，生成可信候选对照；同时定义统一账本事件协议。
2. 实现新旧账户分离、状态机、纯重放账本和完整备份，再接入金额建议。
3. 配置版本、月度计划冻结、限购与切换流程；获用户选择后启用对应候选。
4. 实际盈亏、基准和手机交互；跑Flask/静态页一致性及恢复验收。

每步独立可审查，不运行带自动提交推送的刷新脚本。现有估值观察、历史研究和旧账户保留。所有新功能先在模拟账户通过，不用用户历史数据做破坏性迁移。
