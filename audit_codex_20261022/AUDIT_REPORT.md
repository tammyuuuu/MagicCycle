# 星循第一阶段独立验收报告

日期：2026-10-22。结论：**研究候选可以保留，但 V2.3 的验收不通过，现有网站不能直接承担新策略真实账务。**

本轮完整阅读 HANDOFF_TO_CODEX.md，检查 V2.0–V2.3 报告、V1 历史结论及相关源码、数据、策略注册表；独立调用原始函数复现 V2.3 月度表，再运行日度引擎、重放逐笔账本并检查网站边界。未修改业务源码、正式配置或原研究文件；新增文件仅在本目录。没有提交、推送、删除文件或真实交易。已有大量工作区改动属于接手前状态。

范围说明：本轮重点复跑 V2.3 五个候选与必要对照，没有重新运行历次研究的全部策略搜索、V2.1 的3000组网格或抓取脚本。对这些旧研究的意见属于代码和方法审计，不能等同于逐项重新认证。原始数据未联网更新，以免覆盖交接证据。

## 1. 最重要的发现

### 阻断一：V2.3 主样本和样本外日期标错

`run_v23.py:month_ret` 对所有资产执行 `resample('ME').last().pct_change(fill_method=None).dropna()`，而不是仅对当前组合所需资产检查完整性。

162413 最后有效数据为 2025-01-16。它虽然不在 A/B/C/L1/L2 中，却使整个月度面板在 2025-01 后全部被删除。因此：

| 表中标签 | 原函数实际使用的月收益 |
|---|---|
| 主样本 2021-11～2026-10 | 2021-11～2025-01，39 个月（3.25 年） |
| 样本外 2023-01～2026-07 | 2023-01～2025-01，25 个月 |
| 长样本 2017-07～2024-12 | 90 个月，结束日期未受此缺陷影响 |

交接表 A 的 11.11% / −7.03%、L1 的 9.83% / −2.15% 等数值均能复现，**但不是所声明期间的结果**。这不是手续费能解释的误差，2025–2026 的风险被整段遗漏。

只按组合所需资产计算后，主样本完整月份到 2026-09（59 个月）；月末标签 2026-10-31 超过截止日 2026-10-21，因此原筛选逻辑也会排除十月未完月。对应 A/B/C/L1/L2 的合成 CAGR 为 12.33% / 11.42% / 8.69% / 10.62% / 9.17%，月度 MDD 为 −7.03% / −6.20% / −3.77% / −12.34% / −11.63%。这组数字截止九月，不能与截止十月的日度表直接相减归因。

### 阻断二：动态月度策略存在未来信息泄漏

`run_v23.py:run` 在月末 dt 取 `hist=panel.loc[:dt]`，计算逆波动、ERC 或趋势权重，再乘同一个月的收益。权重已经看到了要预测的当月走势。应使用上月末实际可得数据确定下月权重，并考虑净值披露滞后。

固定权重 A/B/C/L1/L2 没有这项权重泄漏；它们仍受日期错误、月频回撤、零费用和即时再平衡假设影响。V2.3 动态策略 14.60%、16.50% 等漂亮数字应撤回，不能用“黄金牛市”代替代码层面的解释。

### 阻断三：V2.1 的回调参数样本外隔离不成立

`run_v21.py` 仅用起点日期判断训练集（截至 2022-12），随后以 `horizon_end(...,3)` 跑完整三年。因此晚于 2022 年的训练收益一路进入 2025 年，再把 2023 年起点标为测试。

选参看到了测试时期的行情。需按**训练持有期结束日期**截断，或者做带隔离期的滚动验证。不能维持 V2.2 “回调参数泄漏通过”的验收结论。一次性与固定分批本身没有因此自动变成错误，但现有结果不足以认证所有新候选的一次性建仓结论。

## 3. 月度合成到底高估了什么

必须分开比较样本、采样频率与执行成本。

在原表**实际覆盖**的 2021-11-01～2025-01-31 上：

| 方案 | 原月度合成 CAGR / MDD | 日度引擎 CAGR / MDD |
|---|---|---|
| A | 11.11% / −7.03% | 10.95% / −8.53% |
| B | 10.37% / −6.20% | 10.31% / −7.32% |
| C | 8.17% / −3.68% | 8.17% / −4.22% |
| L1 | 9.83% / −2.15% | 9.89% / −4.79% |
| L2 | 8.76% / −2.66% | 8.66% / −4.49% |

结论：**不能笼统说月度合成总是高估年化收益，但它确实隐藏了日内于月度采样之间的回撤，且原表还漏掉后续高风险时期。**

在完整主样本内，对同一条日度引擎净值只做月末采样，A/B/C/L1/L2 的 MDD 变为 −6.71% / −5.82% / −3.59% / −11.99% / −11.43%；原始日度 MDD 则为 −10.92% / −10.10% / −6.59% / −15.40% / −13.84%。这才是隔离采样影响的比较。

完整主样本费率归零后，五方案 CAGR 增加约 0.02～0.03 个百分点，费用不足以解释回撤差距。统一到账改为 5 或 10 个代理交易日的敏感性见 CSV；10 日假设下五方案 CAGR 约 11.85% / 10.97% / 8.46% / 10.44% / 8.93%，排序没有反转。但这不等于真实到账规则已核实。

## 4. 逐笔资金和费用核对

`verify_ledger.py` 独立按成交记录逐日重放 27 组账本（9 方案 × 3 时段）：现金先取得货基收益、到期应收再转现金、买入扣现金、卖出生成应收、份额 FIFO 减少。每日净资产与引擎差异最大 1.82e−12 元；现金未透支；费率按保存阶梯重新计算吻合。

构造案例：2026-01-29 买债 2000，02-03 持有五个自然日赎回，扣费 29.9760 元；02-05 才使用净回款 1968.4253 元买黄金。证明引擎有扣短期赎回费、没有提前使用回款。构造案例仅验证代码机制，不是交易建议。

但以下内容仍不能验收为真实交易引擎：

- 所有基金购买后统一 `avail=i+1`，没有单独实现 QDII T+2 确认。
- 持有期从成交净值日而非可配置确认起算日计算，临近 7 天边界可能错档；代码允许短持卖出并扣费，并非强制禁止七天内卖出。
- 统一 `settle=2` 是模型假设；交接称其“偏保守”没有根据。易方达官方投教说明 QDII/FOF 赎回支付可到 T+10，具体按合同及渠道，见文末来源。
- 没有净值发布时刻、分基金可交易日历；QDII t+1 成交仍可能使用尚未公布的 t 日信息。
- 总收益指数自动假设分红再投资，未建现金分红到账；没有真实份额和逐笔费用分位取整规则；期末未扣假想清仓费用。
- 仅有二元 blocked，不实现历史每日限额、已提交订单占额、失败与退款。现金轨迹字段还把应收合在一起，不等于可用余额。
- 起始日先计一次现金收益；旧 stats 又用第一日净值作分母。影响很小，但正式框架应统一从初始本金开始。

## 5. L1 是否仍是合理候选

**可作为简洁的限购期研究候选保留，但不能作为已验证低回撤方案或自动默认方案。**

完整主样本 L1 10.43% / −15.40%，收益高于 L2，但回撤也更大；长样本 L1 7.51% / −10.31%，L2 7.63% / −7.45%。L1 的 50% 黄金集中风险明显，限购不代表投资者自动接受提高黄金占比。

“K4 被 L1/L2 支配”不成立。用相同主样本日度执行口径重跑 K4（债/金/001214，历史 120 日逆波动，60% 上限）得到约 **7.44% / −7.21%**。L1/L2 收益更高，但回撤约为其两倍，是风险交换，不是收益与风险同时优胜。原 V2.3 表中 K4 −1.90% 本来就小于 L1 −2.15%，原文的严格支配措辞也不成立；其动态月度计算还受前视污染。

这不构成重新默认买中证500的证据。按照用户要求，500/300/科创继续观察，不纳入默认交易。后续应在相同风险预算下比较债/金不同比例、现金腿、L2及其他可购同类资产，并预先确定可承受回撤。

## 6. 是否胜过简单持有

同一初始权重、同一期间、同一申购费，不再平衡是必须保留的基准。完整主样本：

| 方案 | 再平衡 CAGR / MDD | 简单持有 CAGR / MDD |
|---|---|---|
| A | 11.85% / −10.92% | 11.73% / −15.10% |
| B | 10.91% / −10.10% | 10.99% / −14.16% |
| C | 8.46% / −6.59% | 8.64% / −10.80% |
| L1 | 10.43% / −15.40% | 10.99% / −21.54% |
| L2 | 8.92% / −13.84% | 9.37% / −18.59% |

再平衡主要改善回撤，**没有普遍提高收益**。长样本 A/B/C 简单持有年化也高于再平衡。网站不能只与货基比较后宣称策略有效。

## 7. 网站账务审计

本轮审的是本地源码、静态快照和隔离内存中的 JavaScript；没有读取用户浏览器的真实本地账本，也没有验证已发布远端站点。不能宣称用户历史每笔记录都已对账。

| 严重度 | 发现与证据 | 后果 |
|---|---|---|
| 阻断 | `portfolio_store.js:rebuildFromDiary` 从当前 poolCash/receivable 开始，再重放全量日记；隔离案例 2000→买1000后1000→重建0→再重建−1000 | 重建不幂等，重复扣款/增加应收 |
| 阻断 | `applyNewEntries` 只增量消费未处理 id；删除日记后原仓位仍在，修改相同 id 同样不重放 | 日记与持仓/现金分裂 |
| 阻断 | `_qty` 在没有确认份额时按 amount/price 自动估份；填入日记按钮预填旧净值 | 预计份额可能提前变成持仓，且未扣申购费；交接称“设计正确”不实 |
| 阻断 | 无账户 id，同一 profile、全站日记按基线日期加入；非配置持仓也计入 poolValue | 历史持仓污染预算与复盘，单凭“不参与调仓”不能满足账户分离 |
| 阻断 | `renderReview` 只用月初持仓×区间总收益，不按成交日结算 | 新买收益漏算、卖后继续虚算、手续费/现金/应收漏算，不是实际月度盈亏 |
| 高 | 无持仓卖出1000份仍生成1000元应收，超卖只把份额钳到0 | 可凭日记制造资产；买入也可透支成负现金 |
| 高 | `renderPlan` 无月度执行门控，每次都用最新权重；网站买带1%、研究买带2% | 网站行为和研究规则不一致，可能更频繁交易 |
| 高 | 状态包含“暂停”时在判断买卖方向前 return | 暂停申购被错误当成禁止赎回 |
| 高 | 限额截断后不重新检查最低申购；构造5元限额仍生成5元可执行买单 | 最低10元规则失效；未扣当日已提交额度 |
| 高 | 持仓传入 sellable=true，holdDays通常缺失，以单个保守费率估费 | 未实现批次FIFO、确认中份额和七天边界管理 |
| 高 | 净值只校验数值/日期存在，不要求新鲜；缺净值持仓以0参与金额规划 | 数据缺失可能放大新增额度；应暂停整组计算 |
| 高 | 默认“今天无需操作”把没有可执行动作解释为交易带内，并隐藏不可买行 | 暂停/缺数据可能被误报为无需操作 |
| 中 | 只有日记JSON导入导出；profile、总资产快照、flows、应收、策略配置没有完整备份 | 换手机无法完整恢复；静态站域名或浏览器变化也会隔离存储 |

月度反例：月初100份×1元，月中全卖出且实现收益0，月末净值2元，现公式仍算+100元；月初空仓、月中买100元、月末110元，现公式算0元。月初取当月1日净值又可能漏掉上月末到月初的变动。真实公式应基于整个账户：期末净资产−期初净资产−外部净流入。

10%预算、超额暂停新增、申购费包含在支付金额内、未到账赎回款不用于新买等基础纯函数可复用。但不能因纯函数测试通过就把实际账务判为可用。

## 8. 数据与交接一致性

- 四只原始 JS 的 SHA256 与 manifest 一致；独立重新解析后，总收益指数与已清洗文件差异不超过 0.0000005（六位小数舍入）。只能证明文件一致和转换可复现，不能证明供应商数据绝对准确。
- 主样本五方案所需原始基金数据无重复日期；161130 在共同日历仅缺 2026-10-21，末日填前值。因此此次主样本中“大量QDII缺失”不是主要误差源。其他资产、长样本和公布时滞仍要分别检查。
- manifest 的 first/last 用 UTC 日期，clean 用上海日期，表面相差一天是时区口径；不能把 manifest 的日期直接当净值日期。
- `portfolio_data.py` 与 docs 快照仍为 000216/160706/090010/006484 旧配置，此项交接准确；但它**已有逆波动计算函数**，不是完全没有动态权重。缺的是月度冻结和版本执行，不必重复开发求权重模块。
- A/B/C 与 L1/L2 都是固定权重，交接把 L1 写成需要动态逆波动不一致。
- 注册表保留多个旧版本的 executable_now、K4切换推荐；仅新增 v23 字段没有消除可被误读的旧推荐。不同版本 A/B/C 的定义也不同，不能只用字母作正式标识。
- V2.3 把 K4→旧B 的1.3～1.6元额外切换成本套到 L2→新A/B/C，未提供对应交易模拟，不能沿用。
- 旧 `dca.py` 同日收盘成交、低费率、卖出立即可用仍存在；研究引擎的引入没有修复网站 `/api/backtest`。观察/旧回测与新账户决策必须明确区分。
- `update_alerts.ps1` 仍有自动 commit/push。此次未运行它；后续开发验收不能误用其刷新发布流程。
