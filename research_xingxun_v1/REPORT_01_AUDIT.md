## 0. 结论摘要（先看这 8 条）

1. **网站是一套"场内 ETF 信号 + 静态页面发布"系统，不是场外基金交易系统。** 全部行情来自 ETF 价格；你要买的支付宝/微信场外联接基金，只有名称和净值口径差异，系统没有建模。
2. **现有"条件定投"回测存在同日收盘成交的前视偏差**（`dca.py:208` + `dca.py:254`）。信号用当日收盘算出，又用同一收盘价成交；实盘最早只能 T 日 15:00 前下单、按未知净值确认，或 T+1 开盘成交。因此 `app.py` 的 `/api/backtest` 和 `main.py dca` 的历史收益结论**不能直接采信**。
3. **交易成本被低估一个数量级。** 现有回测用 `fee_rate=0.0001`、`min_fee=0`（`dca.py:52-53`）；实际场外申购 0.04%–0.15%、赎回 0–0.5%（7 天内 1.5%）。差额 4–15 倍，且完全没算赎回费。
4. **资金模型与目标不一致。** 现在是"每月固定预算 + 等份上限"（`monthly_budget.js`），目标是"总金融资产 × 10%"，且没有总资产快照、没有 10% 上限校验、没有资金池现金账户。
5. **没有组合层回测，也没有样本外验证。** `backtest.py` 只支持单标的；`research_*.py` 是多轮参数搜索脚本，产出的是 md 结论，不是可复现的统一框架。
6. **相关性与配置模块的方法论偏弱。** 只算 ETF 价格 60/120/250 日 Pearson；没有滚动稳定性、没有下跌期检验、没有策略层相关、没有边际贡献；"轮动推荐"按最低平均相关挑组合，与"不强制轮动"的理念冲突。
7. **投资日记已经能记录真实成交**（日期/代码/金额/份额/价格/快照/复盘），但只存在浏览器 localStorage，且不区分"资金流入"和"投资收益"，无法算真实收益率。
8. **"定时推送"名不副实。** 实际是 Windows 登录时运行 `update_alerts.ps1` → 生成静态页 → **自动 git commit + push**，不是收盘后定时任务，也没有人工复核环节。

## 3. 当前买卖信号逻辑（逐条）

### 3.1 旧宽基：5 年分位 + 回撤档位（`alerts.py:19`，`dca.py:110`）

- 历史最高/最低：过去 1260 个交易日滚动极值，**shift(1)**，即截至昨日（正确）。
- 分位点：当日收盘在过去 1260 个收盘价中的百分位（含当日）。
- 日均波动：60 日绝对日收益均值，shift(1)。
- 条件：
  - A 跌幅足够深：`close <= hist_high × (1 − max_gain × 50%)`
  - B 低位：分位 < 30%
  - D 过热：分位 > 70%
  - C 涨幅足够：`close/成本 − 1 >= max_gain × 50%`
  - E 高位回撤：`(持仓期最高 − close)/最高 >= 日均波动 × 2`
- 买入金额：A且B=30 元 / 仅A=20 / 仅B=10 / 其余 0；D 触发则暂停。
- 卖出优先级：E 清仓 → C+D 清仓 → 仅C 减半 → 仅D 暂停定投。

**问题**：金额档位（10/20/30 元）与 2000 元资金池、10% 预算完全脱节；"历史最大涨幅"随窗口滚动会突变，导致阈值跳变；没有成本/份额/到账约束。

### 3.2 新宽基：估值 + 价格带（`strategies.py:230-265`，`broad_individual_strategy.py`）

- 估值：乐咕月度 PE，按 `as_of` 截断，取 3/5/10 年分位；超过 35 天未更新则"无法判断"（`valuation_data.py:33`）。
- 价格带：距 250 日高点回撤 ≥10% 为"回撤中等"、≥20% 为"回撤较大"。
- 动作：估值低位 + 回撤较大 → 加仓；低位 + 中等 → 买入；估值高位 → 减仓；分位 ≥90% → 退出。
- 参数：`strategy_config.py` 标注 "V1 provisional"。

**问题**：估值数据是月频且发布滞后，代码只用"日期差 ≤35 天"控制，没有"当时是否已公布"的发布日字段；分位阈值（30/90）没有样本外证据；与 3.1 并存会产生相反结论。

### 3.3 黄金（`gold_strategy.py`）

- 过热：20 日涨幅 ≥15% **且** 相对 60 日均线偏离 ≥15% → 目标仓位 1.0→0.5（减半一次）。
- 冷却：20 日涨幅 ≤5% **且** 偏离 ≤5% → 回到 1.0（可加仓）。
- **问题**：目标仓位只有 1.0 / 0.5，没有 0；"加仓"没有金额；用净值而非金价，联接基金跟踪误差未评估。

### 3.4 行业 ETF（`industry_strategy.py`）

- MA20 上穿买入；首次跌破减半；连续 2 日跌破清仓。与多资产配置目标无关。

### 3.5 美股（`us_etf_strategy.py`）

- 月度趋势 + 2% 溢价上限。限购/暂停申购已有处理（`monthly_budget.js:38`），思路可借鉴。

## 4. 数据链路

```
AkShare 东财 ETF 日线(qfq) ─┐
腾讯 fqkline(qfq) ──────────┼→ data_cache/etf_{code}_{source}.csv → 页面/策略
新浪 fund_etf_hist_sina(不复权) ┘
乐咕乐股 月度 PE → data_cache/valuation_*.csv → 估值分位
东财 push2delay → 溢价/限价（仅两只美股 ETF）
```

关键事实：

- `config.py:37` 默认 `ADJUST="qfq"`；`data_fetcher.py:266` **增量**拉取（从缓存最后日期+1），前复权因子变化不会回溯修正旧行 → 同一文件内可能混用不同复权基准，除息日出现假跳空。
- 三源降级时，新浪是**不复权**（`data_fetcher.py:10`），`_stale_cache` 会在前两源失败时返回新浪数据（`data_fetcher.py:377`），但下游策略不做口径识别。
- 交易日历用"工作日 + 15:00"近似（`_expected_latest_trade_date`），没有节假日表；长假后会多请求一次，不会错，但"数据是否最新"的判定偏乐观。
- **场外基金完全没有接入**：没有净值确认日、没有 T+1 份额确认、没有赎回 T+1~T+7 到账、没有未知价成交。

## 5. 预算、日记、复盘

### 5.1 月预算（`monthly_budget.js`）

- 输入：一个月度固定总额（默认 1000 元）+ 勾选 ETF 集合。
- 每只 ETF 上限 = 总额 / 只数；按状态给比例：加仓 100%、买入 50%、小额尝试 25%、配置 50%、试探 10%、观察/减仓/退出 0%。
- 本月建议 = max(0, 上限 × 比例 − 本月该 ETF 已买)，并受全账户剩余额度限制。
- **锁定语义是对的**：首次买入后锁定本月预算与标的，不按当天可买标的重新分配（避免重复计算）。
- 缺失：总金融资产、10% 上限、投资资金池、可用现金、内部调仓 vs 新增投入的区分、费用预留。

### 5.2 日记（`investment_tools.js:15`）

字段：`date / code / name / type / action(买入|加仓|减仓|卖出|观察) / amount / quantity / price / reason / sellPercent / note / snapshot / reviews`。
校验：日期格式、6 位代码、金额>0（观察=0）、份额/价格>0、快照必须与代码和日期匹配、复盘字段合法。
存储：`localStorage["investment_diary_v1"]`，可导出/导入 JSON，导入按 id 去重。

**能做到**：真实成交记录、行情快照留证、事后复盘、预算扣减。
**做不到**：跨设备同步、资金流入流出区分、已实现/未实现盈亏、月度收益、策略理论收益对比、策略版本历史。

### 5.3 复盘

- 复盘选项：后续行情、回看原决策、下一步打算、原因、计划卖出比例。
- 只是文本记录，没有量化归因。

## 7. 缺陷与风险清单

等级：**阻断**＝会让结论失真；**高**＝会导致错误操作；**中**＝影响可维护性/一致性；**低**＝体验问题。

| # | 等级 | 问题 | 位置 | 影响 | 建议 |
|---|---|---|---|---|---|
| 1 | 阻断 | 回测同日收盘成交 | `dca.py:208`、`dca.py:254-283` | 收益被高估，尤其震荡市 | 新框架统一 t 收盘信号 → t+1 净值/开盘 |
| 2 | 阻断 | 申购费 0.01%、无赎回费 | `dca.py:52-53` | 成本低估 4–15 倍 | 用真实费率阶梯（本轮已产出 `clean/fee_table.csv`） |
| 3 | 阻断 | 卖出后现金立即可用 | `dca.py` 卖出分支 | 同一笔钱当天重复使用，违反场外 T+1~T+7 到账 | 加应收款/在途资金账户 |
| 4 | 高 | 前复权缓存不回溯 | `data_fetcher.py:266` | 序列内复权基准不一致，产生假跳空 | 定期全量重拉，或改用"不复权+分红"自算总收益 |
| 5 | 高 | 不复权源混入策略 | `data_fetcher.py:10`、`:377` | 分红日假跌，触发错误卖出 | 数据层标记口径，策略层拒绝不复权数据 |
| 6 | 高 | 两套宽基逻辑结论可能相反 | `alerts.py` vs `broad_individual_strategy.py` | 同一资产两个页面给出不同建议 | 只保留一条主策略，版本化 |
| 7 | 高 | 场外基金未建模 | 全局 | 建议不可执行（未知价、确认、限额） | 新增场外交易模型 |
| 8 | 高 | 预算与 10% 规则脱节 | `monthly_budget.js` | 可能超投或漏投 | 新增总资产快照 + 资金池账户 |
| 9 | 高 | 日记无出入金区分 | `investment_tools.js` | 无法计算真实收益 | 加现金流类型与成本基础 |
| 10 | 中 | 相关性只用价格、只看单一窗口 | `correlation_tools.js` | 低估尾部风险，配置依据弱 | 用总收益、滚动、下跌期、策略层、边际贡献 |
| 11 | 中 | "轮动推荐"与理念冲突 | `correlation_tools.js:recommend` | 用户可能机械轮动 | 改为"候选分散组合"，不输出轮动指令 |
| 12 | 中 | 参数散落三处 | `strategy_config.py`、`DCA_DEFAULTS`、`TARGET_ETFS` | 改一处漏一处 | 单一策略配置文件 + 版本号 |
| 13 | 中 | Flask 与静态导出重复装配 | `app.py` / `export_alerts.py` | 两端结果可能不一致 | 抽出统一 service 层 |
| 14 | 中 | 无策略版本历史 | 全局 | 无法回溯"当时为什么这么建议" | 信号表加 `strategy_version` + 生成时间 |
| 15 | 中 | 自动 commit/push 无复核 | `update_alerts.ps1` | 异常数据也会发布（仅"全部失败"才拦） | 发布前加数据日期/异常校验 |
