## 2. 计算规则（与第三轮一致）

1. 池子目标 = 总金融资产 × 10%；超额只暂停新增，不强制卖出。
2. 池内调仓不算新增投入；新增投入不超过外部可用现金（当前版本外部现金固定 0）。
3. 买入受「池内现金」限制，卖出款先记「在途」，不参与当日买入。
4. 申购费按实际费率：费用 = 金额 − 金额 /(1+费率)，份额 = (金额 − 费用)/净值。
5. 赎回按持有天数阶梯费率；持有期未知时按保守费率（≥7 天档）估算，并在说明中注明。
6. 单笔低于 10 元不下单；日限额会截断并提示。
7. 暂停申购、净值缺失 → 不生成交易；净值缺失的持仓从池子估值中排除并给出警告。
8. 权重合计 >100% 直接拒绝计算。

## 5. 本轮修复的问题

1. **资产顺序错乱**：JS 对象中 `"160706"` 被当作整数键排到最前；改为使用 `allocation.codes` 数组固定顺序。
2. **成交后现金不同步**：买入只改份额导致池子虚增；现在买入同步扣现金、卖出记在途，池子总值守恒。
3. **卖出款当日复用**：原先卖出即加现金，违反 T+2；现改为在途 + 手动确认到账。
4. **基线前复盘**：会凭空显示历史市值；现在早于基线的月份直接提示不可复盘，月中基线自动从基线日起算。
5. **静态导出漏卡片**：`export_alerts.py` 不跑 Jinja，`{% include "_portfolio_v1.html" %}` 未被展开；已手动展开。
6. **移动端溢出**：表格 `nowrap` 撑破 375px；已加媒体查询，文档宽度回到视口宽度。
7. **负现金**：池内现金记录为负时只提示并从 0 起算可花费金额，不生成负买入。

## 6. 已知限制

- 纯前端存储（localStorage），换设备/清缓存会丢；JSON 导出/导入尚未做。
- 「在途资金」需手动确认到账，系统不会自动按 T+2 结算。
- 月度复盘用「月初持仓 × 区间总收益」，不处理月内多次申赎的现金流时间加权。
- 端口/外部现金固定为 0；新增投入目前只能用池内已有现金。
- JS 与 Python 的对齐靠浏览器实测 + 冻结期望值，没有 Node 单测环境。
- 组合只含 4 只基金，不含 QDII 溢价、限购状态变化等。
